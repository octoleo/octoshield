# OctoShield features

OctoShield brings Ubuntu laptop protections into a native GNOME application and a complete Whiptail/command-line interface. It is maintained by [Vast Development Method](https://www.vdm.io) as part of the **Octoleo** suite. Both interfaces use the same Bash modules; C provides the native GTK4/libadwaita interface and bounded event aggregation. The desktop follows system light/dark appearance and uses the supplied OctoShield artwork.

## Named profiles and individual overrides

Conference, Public, Office and Home provide editable starting points. Create another profile by copying one, adjust settings and firewall exceptions, then explicitly apply the saved profile. Change every managed control together or select a different profile for just firewall, USB, network privacy, services or monitoring. The dashboard identifies those overrides and incomplete changes. Home and Office restore original printing, Bluetooth and saved Wi-Fi autoconnect choices while retaining incoming-deny firewall policy, blocked incoming SSH and disabled discovery by default. A location change does not weaken independent update, AppArmor or screen-lock baselines.

Firewall profiles cover UFW's host IPv4 and IPv6 policy for Wi-Fi and Ethernet. Outgoing connections remain allowed. Inbound exceptions specify a port, TCP/UDP protocol, source address or subnet, incoming interface and optional expiry. Profile switching narrows allowances before adding the destination's exceptions, without deliberately disabling or resetting an active firewall. Established connections are not terminated. Returning to a saved original firewall, network or service state is an explicit reviewed action. External configuration changes are reported before replacement rather than silently overwritten.

Permanent allowances persist in UFW. Timed permissions require an enabled, running status observer before application and receive a UTC deadline enforced by the kernel. Each timed rule stops permitting new connections at its deadline even if OctoShield is removed or its observer stops; existing established connections are not forcibly terminated. Unsupported kernel time matching refuses the grant. These rules exist only at runtime, so reload/reboot removes them sooner and they cannot reopen automatically from disk. Apply the profile explicitly if a still-unexpired permission is needed again. OctoShield verifies the runtime rules and deadlines; ordinary `ufw status` omits them. The observer handles status and reconciles expired permission metadata, independently of kernel deadline enforcement. Inert kernel rules remain until the next Apply or reload.

Printing, Bluetooth, incoming SSH and discovery are separate service choices. Printing can be enabled in Conference without switching the firewall or all other protections to Office. Network discovery and printer-specific reachability remain separate decisions. Network privacy settings govern saved Wi-Fi autoconnect, discovery and MAC behavior; newly created connections need their own review. The app does not trust a Wi-Fi name or plugged-in cable as proof that a network is safe, and it does not automatically switch profiles based on a network name.

## Guided access and connection privacy

Access & exceptions groups common services into one reviewed task. The HTTP/HTTPS preset handles TCP 80 and 443 together; SSH and custom ports are also available. Detected physical LAN connections offer their actual interface and IPv4/IPv6 subnets without requiring technical identifiers. One action saves, applies and verifies a permission, and inline Edit/Revoke actions operate on the whole group. Its duration starts after approval, immediately before application. Saved-but-unapplied, active, expired, failed and unknown states remain distinct. The effective firewall profile is selected rather than defaulting to Conference. Unmanaged-firewall adoption, pending edits and external changes require explicit review.

The same page exposes firewall recovery before the permission form. A fresh native finding is shown alongside the previous operation's outcome. Reapply only the selected saved firewall profile, inspect its last transaction, review supported external changes or restore its verified original baseline. Accepted external changes update tracking without changing rules and remain pending until a separate Apply or Restore. Recovery preserves the form for a separate permission decision. Verification recognizes UFW's forwarding-disabled display only with actual IPv4/IPv6 policy evidence.

Connection privacy lists named connections with saved settings, live verification and configuration source paths. Per-connection autoconnect, discovery and Wi-Fi MAC overrides belong to the selected network profile. An explicit reconnect action applies saved changes to an active connection after reviewing the interruption. Missing runtime evidence is reported honestly. Both workflows are available through `octoshield access` and `octoshield connections`; explicit subcommands expose the same fixed operations for experienced users.

## USB decisions stay with the effective USB profile

After physical enrollment, USBGuard blocks unknown devices while approval is pending. Approve the current attachment temporarily or remember the reviewed device/port for the current USB profile. Office approval does not grant Conference approval. Switching reevaluates attached devices and expires temporary permissions. The review identifies devices that could disconnect and refuses deauthorization of detected mounted storage until it is safely unmounted. Device changes during review require a fresh review.

The USB page lists current devices with observed states and direct actions for temporary/profile-specific approval, blocking the current attachment and forgetting remembered approval. The same controls remain available from the CLI, including preparation of an inactive profile's trusted device set. Copying a profile intentionally copies its profile-specific USB approvals. Existing 1.0.0 approval policy is retained separately for explicit restoration.

New blocked devices receive a guided review in the active, unlocked local session: allow once, remember for the effective USB profile, or keep blocked. Closing or cancelling grants no access. The decision is bound to the reviewed attachment and profile; changed devices or profile switches require a fresh decision. The packaged user-session USB agent starts through desktop autostart and when opening the application, independently of optional security-event notifications. Device state refreshes after actions without another password request within the unlocked application. Automatic USB prompts have a user preference; disabling them leaves USBGuard enforcement unchanged. Enforcement does not depend on the window or prompt being available.

## One administrator unlock for the application session

The normal-user desktop process uses the system's PolicyKit dialog to unlock a private administrator session. The system selects eligible administrator identities; OctoShield does not grant access based on the Unix `root` group and never collects or retains account passwords. The session accepts only the application's fixed helper operations. Consequential changes still require review, and closing or locking the application, or locking the desktop, ends its authorization. A new launch requires authentication again. GNOME preferences and notifications continue to run as the desktop user.

## Verified status and additional exposure checks

A background observer publishes sanitized summaries that the GUI and CLI can read without administrator authentication. Indicators distinguish active, inactive, partial, unknown and unsupported results and expire stale observations. Desired settings are compared with observed native policy. Missing tools, incomplete transitions or conflicting changes cannot be presented as fully active protection. The observer also verifies expired permissions are closed and reconciles their metadata under the same operation lock; an unavailable observer means status and bookkeeping require attention while kernel deadlines remain enforced.

Additional observations cover Docker published ports and forwarding, Thunderbolt/USB4 authorization and DMA-protection indicators, Secure Boot and disk-encryption topology. Confirmed encrypted root backing storage is displayed positively while other storage coverage is assessed separately. Docker observations distinguish local bindings from wider publication; forwarding alone is not presented as a verified vulnerability. Manage/Review actions lead directly to details, configuration sources and available changes. Private evidence is not added to the world-readable status cache.

Supported Docker Compose projects can receive a reviewed localhost-port override and selective service recreation, running with the normal user's existing Docker permissions. Source/configuration mismatches, unsupported network modes and unsafe source paths refuse automatic repair. Future deployments must include the generated override to preserve its restrictions. Docker forwarding/firewall management remains intact. VM and rootless networking remain explicitly unverified until their own adapters exist. Container-published traffic can bypass ordinary host-input filtering; a UFW indicator does not certify every network path. Disk encryption and firmware settings remain inspection-only.

Baseline controls retain the original explicit operations for UFW setup, USB enrollment, network privacy, service restrictions, GNOME locking/media behavior, Ubuntu security updates without automatic reboot, and AppArmor in existing profile modes. Optional event collection provides bounded firewall, USB and authentication notifications. Private action history and configuration snapshots support deliberate recovery; they are not general file backups or Restic/S3 integration.

## Reviewed system repair

**Recovery & updates → Repair system** and `octoshield repair` inspect a fixed catalogue of known cleanup operations for retired OctoShield functionality. Each applicable repair explains its impact before confirmation and runs within one administrator operation, with private backups and post-change verification. Repeating the action rechecks native state and leaves completed repairs alone. Modified or unsafe configuration is preserved and reported for review.

The first repair retires the former **Fresh administrator authentication** policy. It removes the unchanged generated zero-timeout sudo drop-in or restores the verified configuration that activation replaced. The complete sudoers configuration is validated; other administrator rules determine the resulting authentication grace period. Installation and upgrade preserve native policy until the user chooses repair. This action does not change account passwords, select a protection profile, or broadly reset system settings. Ordinary password changes continue through the system's own account tools, and the GUI retains its independent administrator session.

## Installation, updates and limits

The versioned Debian package installs both interfaces and the compiled monitor. Opening a newer matching `.deb` with the system package installer upgrades the same package, retaining settings and snapshots. The package starts the status observer but never activates a security profile automatically. **Check for updates** uses only the fixed official GitHub release source on request; it offers a validated matching package link and leaves installation/administrator authentication to the package manager. A separately configured signed APT repository remains an optional update path. Native AppStream metadata includes feature descriptions, publisher identity and release screenshots.

The standalone CLI remains available without GTK or GNOME dependencies. Supported targets are Ubuntu 24.04 and 26.04 with systemd; desktop actions require a local user session. App-store discovery and package-installer availability depend on the Ubuntu frontend. See the [README](../README.md), [distribution guide](distribution.md) and [recovery guide](recovery.md).

OctoShield reduces exposure without guaranteeing protection against every attack. USB identities can be imitated; firmware, early boot, malicious trusted hardware and vulnerabilities in permitted software remain outside these controls. Interrupted changes may leave partial state and require targeted recovery. Validate behavior on the actual laptop using the [hardware checklist](testing.md#hardware-acceptance-checklist); fixture and container success alone does not prove physical protection.
